# SoC mod workspace setup

Everything here was verified on SoC 1.0006 (GOG, Russian, xrCore build 3312). Other skills in this
family: `stalker-soc-test-loop` (run and drive the game from Claude's shell), `stalker-soc-lua`,
`stalker-soc-npc`, `stalker-soc-quests`, `stalker-soc-items`, `stalker-soc-spawn`, `stalker-soc-art`.

## Golden rules

1. **Never modify the user's game install.** Work in a copy: `bin\` copied, `gamedata.db*` hard-linked
   (same volume) so it costs no disk. Never write to the hard-linked `.db` files.
2. **Sources vs outputs.** Hand-edited sources live in `src\` (UTF-8). `game\gamedata\` is a build
   output (cp1251), rebuilt by `src\tools\build.ps1`. Art and spawn are generated by scripts too.
3. **One prefix for everything new** (scripts, sections, info portions, string ids, spawn names),
   e.g. `mymod_`. Easy to grep, no vanilla collisions.
4. **Override vanilla files by patch, not by copy-and-edit.** `src\tools\overrides.ps1` lists exact
   find/replace edits applied to the vanilla file from `unpacked\`. Each anchor must match exactly
   once or the build stops. Mark inserted code with `-- <PREFIX>:` / `<!-- <PREFIX>: -->`.
5. Commit after every task that works.

## Scaffold a workspace

```powershell
& "<skills>\stalker-soc-project-setup\scripts\new_workspace.ps1" `
    -Root C:\stalker-mymod -Prefix mymod `
    -GameDir "C:\Program Files (x86)\S.T.A.L.K.E.R. Shadow of Chernobyl" `
    [-ToolsFrom C:\stalker-modding\tools]      # reuse already-downloaded tools
```

It creates (and never overwrites existing files):

```
<Root>\
  game\            working copy: bin\ (copied), gamedata.db* (hard links), fsgame.ltx (patched), gamedata\ (build output)
  appdata\         $app_data_root$: logs\, savedgames\, mod_ipc\ (dev channel), user.ltx (windowed 1280x720)
  unpacked\        vanilla gamedata, read-only reference (fill with the converter, below)
  work\            scratch (decompiled spawn, icon work files)
  tools\           third-party tools (converter, ACDC, texconv, git)
  downloads\
  src\mod\         UTF-8 sources mirrored into game\gamedata\ (config\, scripts\, ...)
  src\tools\       build.ps1, apply_overrides.ps1, overrides.ps1 (+ test-loop tools)
  src\names.txt    optional {N:key} name tokens (one place for translated proper names)
  .gitignore
```

The scaffold also sets the `HIGHDPIAWARE` compatibility flag for the copy's `XR_3DA.exe` (per user,
that exe path only) so captures and clicks work under Windows display scaling.

`fsgame.ltx` gets two edits: `$app_data_root$` points to `<Root>\appdata` (saves/logs stay out of
Documents and away from the real game's saves), and a `$mod_ipc$` alias (`appdata\mod_ipc\`) is added
for the dev command channel (see `stalker-soc-test-loop`).

## Unpack vanilla gamedata

Tool: xray_re-tools `converter.exe` (github.com/abramcumner/xray_re-tools, 0.3.1).

```powershell
foreach ($db in Get-ChildItem "<GameDir>\gamedata.db*") {
    & <Root>\tools\xray_re-tools\converter.exe -unpack $db.FullName -2947ru -dir <Root>\unpacked
}
```
`-2947ru` = SoC 1.0006 Russian; use `-2947ww` for the worldwide build. ~25,700 files. Useful
references inside: `scripts\lua_help.script` (every exported class/function signature),
`config\system.ltx`, `config\gameplay\*`, `config\text\rus\*`.

## Build

`src\tools\build.ps1` (template in `templates\`):
- copies `src\mod\**` to `game\gamedata\**`; text files (`.xml .ltx .script .txt`) are transcoded
  UTF-8 -> windows-1251 and an `encoding="UTF-8"` header becomes `windows-1251`;
- replaces `{N:key}` tokens from `src\names.txt` (fails on unknown keys);
- replaces em/en dashes and guillemets (the game fonts lack them) and **fails on any character
  outside cp1251** instead of silently writing `?`;
- runs `apply_overrides.ps1` -> patched vanilla files + `$Copies` (vanilla folders copied as-is).

Run it before every test launch. Blender/spawn scripts write straight into `game\gamedata\`.

## Hooking the mod into the game (first overrides)

`templates\overrides.ps1` already contains the standard hooks:
- `config\system.ltx`: `#include "<prefix>\<prefix>_system.ltx"` **at the very end** (LTX parents
  must be defined before children, so mod sections that inherit vanilla ones go last); plus
  registration of the mod's xml lists: `npc_profile`, `character_desc`, dialogs, info portions,
  encyclopedia.
- `config\localization.ltx`: string table files.
- `scripts\bind_stalker.script`: calls into `<prefix>_main` on actor spawn, update, item take/drop,
  take from box (see `stalker-soc-lua`).
- `scripts\_g.script`: `printf` made a real no-op (`log()` does nothing in retail, but printf still
  runs `string.format`, which raises on missing arguments inside vanilla code paths).
- `config\gameplay\game_tasks.xml`: `#include` of the mod's task fragment.

Anchor strings must match the vanilla text exactly (CRLF is normalized). If an anchor is not unique,
extend it with the neighbouring line.

## .gitignore

Track `src\`, `game\gamedata\`, docs. Ignore `unpacked\ downloads\ tools\ appdata\ work\ game\bin\
game\gamedata.db*` (template: `templates\gitignore.txt`). Portable git: MinGit zip from
github.com/git-for-windows/git releases into `tools\git`.
